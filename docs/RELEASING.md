# Releasing the Dispenser Android app (GitHub Releases)

Status: release engineering is in place and `0.5.0-beta.1` is being prepared. Until the
repository `Nowass/dispenser` is public, the in-app update check reports that release
information is unavailable (unauthenticated GitHub API returns 404). No credentials are ever
embedded in the app.

## Build variants

| | Release | Debug |
|---|---|---|
| applicationId | `cz.nowass.dispenser` | `cz.nowass.dispenser.debug` |
| Launcher label | Dispenser | Dispenser DEBUG |
| versionName | `0.5.0-beta.1` | `0.5.0-beta.1+debug` |
| Signing | local release key (optional, see below) or unsigned | Android debug key |
| BLE device features | hidden: Settings shows the disabled "coming later" placeholder | enabled (pairing, invitations, phones) |

The two variants are separate apps and can be installed side by side. `+debug` is SemVer build
metadata: the update checker ignores it, so a debug build compares equal to its base version.

The BLE device features are switched per build type (`device_features_enabled` in
`android/app/build.gradle.kts`): off in release builds until hardware acceptance, on in debug builds.
`testReleaseUnitTest` runs only the build-type checks (`src/testRelease`) and fails if a release
build would offer them.

## Versioning

- `versionName`: **semantic versioning** (`MAJOR.MINOR.PATCH`, optional pre-release such as
  `0.5.0-beta.1`). The app compares versions by SemVer precedence, never as strings.
- `versionCode`: **strictly increasing integer for every published APK**, including
  pre-releases; assigned manually in `android/app/build.gradle.kts`, never reused, never derived
  from the version number. Sequence: `0.5.0-beta.1` → 5, `0.5.0-beta.2` → 6, `0.5.0` → 7.
- Current: `0.5.0-beta.1` / 5 (first release, prepared 2026-11-15). The previous development
  builds were `0.4.0` / 4 (debug-signed, never published).

## Update channels (installed build decides; never switched automatically)

- **Stable build** (versionName without pre-release): considers stable releases only.
- **Beta build** (pre-release versionName): considers beta *and* stable releases and offers the
  newest newer one. A beta user therefore receives `0.5.0` when it is published.
- The app shows the newest newer release that has an `.apk` asset and opens its official
  `https://github.com/...` release page. It never downloads, installs or executes anything.

## Release signing

### 1. Generate the release key (once, by the project owner, outside the repository)

```sh
mkdir -p ~/secure/dispenser && chmod 700 ~/secure/dispenser
keytool -genkeypair \
  -storetype PKCS12 \
  -keystore ~/secure/dispenser/dispenser-release.p12 \
  -alias dispenser-release \
  -keyalg RSA -keysize 4096 \
  -validity 10950 \
  -dname "CN=Nowass, O=Dispenser"
chmod 600 ~/secure/dispenser/dispenser-release.p12
```

- `keytool` prompts for the password; use a long random password generated by a password
  manager. With PKCS12 the key password is the same as the store password.
- 10950 days ≈ 30 years. The key can never be replaced for existing installations: Android only
  installs an update signed with the same key.
- Never place the keystore inside the repository; `.gitignore` blocks `*.p12`, `*.jks`,
  `*.keystore` and `keystore.properties` as a safety net only.

### 2. Record and back up the key

```sh
keytool -list -v -storetype PKCS12 -keystore ~/secure/dispenser/dispenser-release.p12 -alias dispenser-release \
  | grep 'SHA256:'
```

- Write the certificate SHA-256 fingerprint into this file (section "Release certificate")
  and the README in a normal commit; it is public information.
- Store the password in a password manager entry ("Dispenser release key").
- Keep at least **two encrypted offline copies** of `dispenser-release.p12` in different places
  (e.g. an encrypted USB drive at home and an encrypted archive in personal cloud storage), e.g.
  `gpg --symmetric --cipher-algo AES256 dispenser-release.p12`.
- Test each backup: restore it to a temporary directory, run the `keytool -list` command above
  against the copy and compare the fingerprint, then delete the temporary copy.
- Never send the keystore or password by e-mail/chat and never add them to GitHub Actions.

### 3. Configure local signing (outside Git)

Add to `~/.gradle/gradle.properties` (user home, not the repository), then `chmod 600` it:

```properties
dispenser.signing.storeFile=/home/<user>/secure/dispenser/dispenser-release.p12
dispenser.signing.storePassword=<password>
dispenser.signing.keyAlias=dispenser-release
dispenser.signing.keyPassword=<password>
```

- Without these properties the release build stays **unsigned** (`app-release-unsigned.apk`);
  CI and pull requests always build that way.
- If only some of the four properties are set, the build fails with the names of the missing
  ones (values are never printed).
- Gradle stores configuration-cache entries encrypted; for extra caution build releases with
  `--no-configuration-cache`.
- Signing uses APK Signature Scheme v2 + v3 (minSdk 26; no v1/JAR signing).

### Release certificate

The permanent release key (generated 2026-11-15, backed up by the owner) is the only identity
for official APKs. Every published APK must be signed with exactly this certificate:

| | |
|---|---|
| Alias | `dispenser-release` |
| Owner | `CN=Nowass, O=Dispenser` |
| Algorithm | RSA 4096, SHA256withRSA |
| SHA-256 | `32:C2:4A:F8:B4:13:8D:49:CF:E8:D8:C6:95:19:A2:6D:44:2D:F6:4C:AF:F5:BE:E7:C7:29:56:FA:C7:CE:64:29` |

`tools/package-release.sh` checks this fingerprint by default. To check a downloaded APK:
`apksigner verify --print-certs dispenser-<version>.apk` and compare the
"certificate SHA-256 digest" with the value above (same hex digits without colons).

## Release procedure (example: `0.5.0-beta.1`)

1. **Clean state:** on `main`, working tree clean, CI green.
2. **Version:** `versionName` / `versionCode` in `android/app/build.gradle.kts` (here
   `0.5.0-beta.1` / 5; the next one must be higher).
3. **Changelog:** move the items from `## [Nevydáno]` under a new heading
   `## [0.5.0-beta.1] – YYYY-MM-DD` and leave an empty `## [Nevydáno]` section above it.
   Check: `tools/release-notes.sh 0.5.0-beta.1`.
4. **Commit** the version/changelog change (`chore(release): 0.5.0-beta.1`).
5. **Verify and build** from that commit:

   ```sh
   cd android
   ./gradlew clean assembleDebug test lintDebug assembleDebugAndroidTest checkThirdPartyLicenses
   ./gradlew --no-configuration-cache assembleRelease      # signed with the local key
   cd .. && tools/package-release.sh      # checks the release certificate below by default
   ```

   `tools/package-release.sh` refuses unsigned, debug-signed or wrongly signed APKs and writes
   `dist/dispenser-0.5.0-beta.1.apk`, `dist/dispenser-0.5.0-beta.1.apk.sha256` and
   `dist/release-notes-0.5.0-beta.1.md` (`dist/` is git-ignored).
6. **Install test** on a device (see "Migrating an existing debug installation" for the first
   release).
7. **Publish** (owner only, after the repository visibility decision):

   ```sh
   git tag -a v0.5.0-beta.1 -m "Dispenser 0.5.0-beta.1"
   git push origin main v0.5.0-beta.1
   gh release create v0.5.0-beta.1 --prerelease --title "Dispenser 0.5.0-beta.1" \
     --notes-file dist/release-notes-0.5.0-beta.1.md \
     dist/dispenser-0.5.0-beta.1.apk dist/dispenser-0.5.0-beta.1.apk.sha256
   ```

   Pre-releases are marked **pre-release** on GitHub *and* use a SemVer pre-release version.
   Stable releases omit `--prerelease` and use a plain version (`v0.5.0`). Attach exactly one
   APK per release; the `.sha256` file is not an APK and is ignored by the update checker.
8. **After publishing:** verify "Zkontrolovat aktualizace" on an installed build, then start
   the next `## [Nevydáno]` items.

The build is repeatable from a tagged commit with the pinned toolchain (Gradle wrapper 9.6.0
with checksum, JDK 25 daemon, AGP/Kotlin versions in `android/gradle/libs.versions.toml`);
byte-identical APKs across machines are not guaranteed.

## Migrating an existing debug installation to the first signed release

The first release (`cz.nowass.dispenser`, release key) cannot be installed over a debug-signed
`cz.nowass.dispenser` (signature mismatch), and uninstalling deletes the app's data. Android
system backup is disabled, so data moves only via the manual JSON backup:

1. In the old app: Nastavení → Záloha a obnovení → export **with** and **without** simulation;
   copy both files off the phone.
2. Install the new debug build (`cz.nowass.dispenser.debug`, "Dispenser DEBUG") next to the old
   app and restore the backup there to prove the file is complete. The old app is not touched.
3. Only then uninstall the old `cz.nowass.dispenser`, install the signed release, restore the
   backup and check the data. Keep "Dispenser DEBUG" until everything is confirmed.

Never run instrumented tests (`connectedAndroidTest`) against a phone with real data: the test
run uninstalls the app under test afterwards.

## Continuous integration

`.github/workflows/android.yml` runs on pushes and pull requests to `main` with read-only
permissions and no secrets: debug build, JVM unit tests, lint, instrumented-test compilation,
unsigned release build and `checkThirdPartyLicenses`. The job summary reports JVM tests as
executed and instrumented tests as **compiled, not executed**. Only test/lint reports are
uploaded (7 days). Gradle wrapper checksums are validated by `gradle/actions/setup-gradle`.

## After the repository becomes public

1. Set `dispenser.github.sourceLinkEnabled=true` in `android/gradle.properties` to show
   "Zdrojový kód projektu" in About (next release).
2. Verify the update check against the published release.

## Third-party licenses

After any dependency change run:

```sh
./gradlew :app:generateThirdPartyLicenses
./gradlew :app:checkThirdPartyLicenses
```

The generator reads the resolved release runtime classpath and each POM (with parent-POM
inheritance) and fails if a license cannot be determined or an attribution-requiring license
(e.g. BSD-3-Clause) has no per-library notice in `app/src/main/assets/licenses/notices/`.
